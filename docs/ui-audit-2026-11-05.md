# ARK UI audit, 2026-11-05

## Scope and evidence

This audit answers a pasted brief about a "multi-view product". The brief matches two sources. They differ.

- `design/current-ui.html` and `design/current-ui-preview.png`. This is a stale offline preview (2026-10-28, still named ATOM, Daylight theme). The brief's Dashboard text describes it almost line by line.
- The native app. Evidence: golden shots in `tests/ui-golden` (2026-11-02 to 2026-11-05): `13-helpers-dashboard`, `42-studio-dark`, `31-chat-t3-dark`.

Checked in code: `design/ark-design-system/DESIGN.md`, `tokens.css`, `AppTypography.swift`, `AppTheme` in `Theme.swift`.
Not checked: hover states (a still image cannot show them), VoiceOver labels, live window sizes.
No file was changed except this one.

## A. Slop inventory (confirmed items only)

1. Board: idle state wears the loudest colour. Five green pills outweigh the one amber "need you". Breaks DESIGN.md "status colour on less than 5% of a screen".
2. Dashboard: six equal KPI tiles. Four of them show zero or routine values.
3. Dashboard: gradient fill under the Void trend line.
4. Rail: icons only. Chat and Board look alike at a glance.
5. Shell: Chats shows a second column. Board shows none and uses a back chevron. Chat shows the model above the title. Board does not.
6. Preview file: stale name (ATOM) and stale palette. It misleads reviewers.
7. Daylight accent `#5B50E6` is indigo on near-white. This is near the "purple-on-white" pattern. Keep it: DESIGN.md sets it. Flag only.

## B. Patterns to keep as primitives

1. Persistent rail, top bar and main pane.
2. Flat surface, hairline edge, lighter step for depth (DESIGN.md section 6).
3. Status as dot plus word. Fix only the idle case.
4. Studio blueprint canvas. It is the one strong contrast anchor in the app. Do not tone it down.
5. Chat layout: open assistant text, bubble for the user, composer chips.

## C. Standard (changes to the brief)

- **Base colour.** Keep Void at `#141414`. Main text `#F0F0F0` on `#141414` is above 15:1, already AAA. The brief's `#0a0a0a` adds nothing and would break the test that ties `tokens.css` to Swift. Fix DESIGN.md instead.
- **Typography.** The Swift scale wins (2026-11-01 redesign): 11, 13, 15, 20, 28. The brief names the same scale. Update DESIGN.md and `tokens.css` to it.
- **Hairlines.** The brief calls them decorative. DESIGN.md makes them the card edge in Void. Brand rule wins. Keep.
- **Idle status.** Idle shows a neutral word, no colour. Colour only for working, needs-you and problem.
- **Links.** A text control gets hover and pressed states (check first; not verified).

`tokens.css` also disagrees with Swift on type. ThemeTests covers colour. It does not cover the type scale.

## D. Action plan

1. **Docs and tokens (no visible change).** Fix DESIGN.md colours and type scale. Set `tokens.css` type to 11, 13, 15, 20, 28. Add a test that compares the scale. Retire or rebuild `design/current-ui.html`.
2. **Calm the Board.** Remove the green pill from idle agents. Keep dots for working, needs-you, problem. Updates 3 goldens.
3. **Dashboard.** Remove the gradient fill. Fold zero-value tiles into one line ("All quiet"). Updates the dashboard goldens.
4. **Rail labels.** Add a text label under each rail icon, or show labels on hover. Needs a decision on rail width.
5. **Shell parity.** One header pattern for every view.

Each of 2 to 5 changes the look. Each needs an ADR and a golden update. Do them one at a time.

## E. Brief

### Routing

```text
Rail (persistent)
 ├─ Home      -> Dashboard
 ├─ Chats     -> list column + chat pane
 ├─ Board     -> Studio | Needs you | Tasks | Team | Activity
 ├─ Schedule
 ├─ Brain
 ├─ Apps / Helpers
 └─ Settings  -> pages (Stats, Appearance, Design system ...)
Top bar: back, title, team status. Same on every view (item 5).
```

### Token spec

Use `design/ark-design-system/tokens.css`. After step 1 it equals the Swift themes for colour and type.

### State contract

No new layer. Runtime sends events. `IslandModel` holds the state. Views read it. A view never holds a copy that outlives its event.

### Viewports

Two sizes exist in goldens: standard and compact (`42-studio-compact`). The pixel sizes are not checked in this audit. Confirm them before any layout work.
