# Bounded Codex advisory children

Implemented 2026-10-18, ADR-164. This supplies one generation of tool-free review children. It does not implement unrestricted nested workers, child tool grants or recursive delegation. Tests/live acceptance remain skipped by request.

## Parent and child scope

A root Codex worker receives `atom_ConsultWorker` when another available worker is listed. It accepts exactly `subagent_type`, `description` (nonempty, <=80 characters) and `prompt` (complete supplied review context, nonempty, <=1,000 characters). A referenced path or URL is just text; the child cannot read it. Secret-shaped titles/context are refused. Parent requests reserve one of two attempts before admission; they run one at a time, including cleanup. Invalid/denied requests also consume attempts. A started child that stops/fails exhausts further consultations in that parent, preventing replay through a different worker.

Only an active root native task in the same chat can admit a child, and the target must be a different currently available non-improver worker from the parent's offered list. A plan-first parent must obtain its existing ExitPlanMode approval first. Child admission bypasses the foreground Agent plan-claim/retry/worktree path; it cannot claim another root work-plan portion or consume the parent's reserved retry identity. The store transaction repeats parent/chat/depth/availability checks, enforces at most two retained advisory children and one running child, and persists a running child with the existing parent_id/chat links and a separate scope marker.

The child uses the target worker's identity (bounded to 8,000 instruction characters) and explicit available Codex pin, otherwise its parent's captured Codex model. An unavailable pin refuses before job/provider creation; Claude pins/provider fallback never apply. Pin changes affect a subsequent consultation, not an already running child. Existing usage metering attributes the child's requested/actual model and tokens to its own job in the source chat. Two attempts/60 seconds are not a fixed monetary or provider-token budget.

Every child gets a separate ephemeral signed-in Codex session and an empty host tool catalog. It receives only its identity, the fixed advisory contract and its saved 1,000-character question/context. It gets no chat/history/memory payload, project/worktree/files, shell/commands, web, browser, external MCP, assigned skills, inherited approvals or child-worker router. Its file/network/native-tool lockdown is the existing Codex host profile. The native policy gate also denies every tool for a persisted advisory job as defense in depth. Identity/task text cannot widen that scope. Child plan-first settings confer no tools or permissions; this path produces advice only and cannot approve a plan or perform changes.

The report contract asks for <=150 words, findings based on supplied context and uncertainty/what the parent must verify. Successful reports must persist as done before return, are secret-scanned/redacted and clipped to 4,000 characters, and carry an explicit unverified-advice envelope. Identity/model output may still contain inaccurate claims; the parent is instructed to verify findings through its own permitted tools. The child is not an independent source or evidence that files/sites were inspected. Limits on returned text apply after provider receipt/buffering, not to total transport memory.

## Ownership, Stop and recovery

The child has a real linked Board row, an Advisory title/step, report and model/usage record. The parent tool observation uses existing generic start/end timing without question/context/report bodies. The native helpers payload adds optional `advisory: true`; older payloads decode false. Board details label supplied-context-only advice, retain Stop and link to a listed parent. Independent Retry/Interrupt/Start fresh controls are hidden and native state guards also refuse them. Existing child links appear in the parent's task thread. Parent/child questions and reports retain the existing private task/report storage and retention behavior, not a new conversation archive.

The parent tracks owned child promises and controllers. Parent Stop/request cancellation, failure/finish, router shutdown or removal cancels children and closes their provider sessions before parent final cleanup; current task/worker availability is polled every 200 ms as well. Parent Stop/removal also marks linked active advisory children stopped in the store. Stopping a child cancels only that child; its parent can continue with existing context but cannot auto-consult again. The child has a 60-second gateway deadline, no retry and the parent's existing overall gateway deadline. Direct process cleanup uses the existing Codex adapter; no generic descendant supervisor or independently schedulable background run is added.

An additive jobs.native_scope column stores advisory scope independently of the display parent link. Native Retry/queueNativeRetry and legacy Interrupt reject scoped children even after restart or parent deletion/unlinking. Native start-fresh/comment wake paths do not independently replay them. Startup recovery retains an unfinished child as failed/interrupted with a review-specific explanation; nothing dispatches automatically. To request more advice, use a new parent task/review. A parent explicitly retried by the user gets its normal fresh attempt and bounded consultation budget; earlier children never resume.

The store's generic Retry action may still exist on older native clients or other surfaces; the host rejects it with an actionable message. This change does not make old clients understand the new label or proactively disable controls they do not recognize. The marker is scope metadata, not an approval, credential or broad grant. Removing a child can remove its stored relation/report; it does not refund the current parent's in-memory attempts. Removing a parent can leave the child without a display link, but its scope/retry restriction remains.

Existing external-data taint is copied from parent to child at admission and returns through normal cleanup; consultation does not clear the parent's taint or confer approval for persistent/outbound tools. No skill-use accounting, worktree, checkpoint or browser lane is created for an advisory child. It cannot introduce an external action whose outcome needs reconciliation; existing parent effects still have their existing limits.
