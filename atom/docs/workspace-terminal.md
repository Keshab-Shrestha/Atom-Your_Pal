# Terminal in Workspace

ADR-186, 2026-10-21. A user-operated interactive zsh beside an active project chat. Choose Workspace → Terminal (also View → Terminal, Option–Command–5), review the scope and choose **Start shell**. Choosing the surface never starts a process. Plain/shared/read-only/archived/missing project chats cannot launch it. The project folder is checked again at Start; a moved or linked root must be reopened through Projects.

The shell runs as the signed-in Mac user. Its initial directory is the project folder; it is **not sandboxed to that folder**. Commands may change files, access the network, read the user's files, launch programs and have external effects. ATOM's agent approvals, Full access choice, file checkpoints and Undo do not govern these user commands. No administrator elevation or new macOS permission is requested. Terminal has no model/tool/private-host dispatch route; the existing computer policy also refuses controlling ATOM's own `dev.atom.*` app identity, including this embedded terminal. Commands and output are not automatically attached to prompts. Existing optional screen context is an independent setting and can still see visible terminal text.

## Interaction and lifetime

- Native terminal emulation, ANSI output, keyboard input, selection, normal user copy/paste, Ctrl–C and PTY resize. A five-surface tab row falls back to a current-surface menu at narrow widths; the chooser and native View commands remain available.
- Explicit **Stop** forcibly ends the shell and normal foreground/background jobs in its Unix session. Unsaved program work can be lost. Closing Workspace, switching surfaces/destinations or closing the main window stops the shell. The stopped buffer remains in memory until a new Start or scope reset; it never silently resumes.
- Changing the current chat/project/root/read-only identity, conversation reset, runtime stop/restart or app quit discards terminal state. Each Start creates a fresh emulator and PTY. No terminal command, output, session or working directory is stored in chat history, the database or UserDefaults. The surface preference alone can persist.
- A minimal explicit environment omits inherited provider keys, agent/runtime variables and shell hooks. `/bin/zsh -f` skips user startup files; normal system `/etc/zshenv` still applies. History saving starts disabled. A user command can explicitly load configuration, enable history or launch a detached daemon.
- Output escape sequences cannot read/write the clipboard, open links/apps, set the app/window title, change the selected project or export iTerm content through the embedding delegate. Normal intentional keyboard copy/paste remains available. Scrollback is 2,000 lines and image cache 4 MiB. Queued PTY input is bounded at 4 MiB; a paste exceeding capacity is refused whole, never silently truncated into a different command.

## Implementation boundary

`WorkspaceTerminalSession` owns SwiftTerm's native `TerminalView` and implements its delegate explicitly. It does not use `LocalProcessTerminalView`, whose default clipboard/link handlers would introduce unwanted side effects. SwiftTerm is pinned to MIT-licensed 1.19.0 (464df5207fc2432e16c9a23abe538187196daf5f); the license and resource bundle ship in the app. Swift's standard library has no VT emulator, and the existing speech dependency does not provide one. Reviewed the upstream package manifest, build-info generator and delegate/PTY APIs. The generator reads source-control metadata; no package plugin installs tools or accesses credentials. ArgumentParser is a resolved upstream executable dependency, not used by ATOM's terminal.

`WorkspaceTerminalProcess` in the testable core owns nonblocking PTY input/output, a process exit source and a single reaping path. The small C target uses `forkpty` and only POSIX operations between fork and exec, changes directory without shell interpolation, resets inherited signals and closes inherited descriptors except terminal stdio and a close-on-exec error channel. Failed chdir/exec is reported before Start succeeds. The shell PID remains owned and unreaped through Stop; session jobs are frozen/ended, then the exact child is reaped. No delayed PID-based kill can target a reused PID. Late native output callbacks compare the current process object before feeding a replacement view.

This is ordinary local shell execution, not a security boundary or a service supervisor. Processes that deliberately detach into another session, external effects and all possible spawn races are outside its cleanup guarantee. Shell programs can use ordinary OS APIs, including the clipboard/network/filesystem, independently of denied terminal escape handlers. ATOM does not undo those effects.

Build/test scripts use SwiftPM's native build system: the newer Swift Build engine otherwise requires an optional, separately downloaded Metal compiler for SwiftTerm's resource even when using its default CPU renderer. The packaged shader source remains relocatable for the optional renderer. The native SwiftPM engine currently emits a deprecation warning; adoption of a future replacement should preserve resource packaging and the macOS 14 deployment target.
