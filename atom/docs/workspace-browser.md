# Browser beside chat

ADR-185, 2026-10-21. Adds a real native Browser surface to Workspace alongside Files, Changes and Git. Browser works in plain chats too; the file surfaces retain their active-project checks. Existing pane width, compact fallback, visibility and saved surface preference continue to apply. View → Workspace: Browser uses Option–Command–4; Files/Changes/Git retain 1/2/3.

The browser has an address bar with Return/Go, Back/Forward, Reload/Stop, page title/loading/error feedback and Reset session. HTTPS addresses can omit their scheme. Local development previews accept localhost, 127.0.0.1 and ::1 with HTTP. Other protocols, embedded credentials, public HTTP and local files refuse. Links opening another window stay in this pane. No destination opens automatically.

The session and page remain in memory across pane close/reopen and surface changes in the same chat. Changing chat/project/root/read-only identity, conversation reset or runtime restart clears the page, navigation history and temporary website data. Reset clears the session explicitly. Only the surface name/width persist to settings; addresses and website contents are not stored there. A hidden page may continue ordinary website activity until reset or scope change.

## Integration boundary

This is a user-operated WebKit view, separate from ATOM's agent-owned Playwright Chromium profiles. Existing worker browser grants, approval checks and Codex/Claude adapters are unchanged. There is no JavaScript-to-host message handler, provider tool, injected model context, automatic page read or new file/tool grant. Direct website forms are user interactions, not agent actions. Computer-control access retains its existing permission boundary. Independently enabled screen-context/capture can still include visible page content under its existing rules; this surface adds no new automatic capture.

Each new view uses a new nonpersistent website data store, without importing Safari or worker cookies. Navigation and response delegates validate URLs; local-file/external-scheme navigation, downloads and unsupported MIME types refuse. File pickers/native drops, camera/microphone requests and website dialogs are disabled in this initial surface. Geolocation is explicitly denied on macOS 27's delegate; older systems retain WebKit/macOS authorization behavior. HTTP authentication prompts refuse; standard server-trust handling is retained and no certificate bypass is offered. More complete website dialogs/uploads/downloads and agent-browser attachment remain separate capabilities.

The bundle enables only NSAllowsLocalNetworking for development previews. It does not exempt all web content or URLSession from ATS. Configuration references: [Apple website data stores](https://developer.apple.com/documentation/webkit/wkwebsitedatastore), [WebKit UI delegates](https://developer.apple.com/documentation/webkit/wkuidelegate), [local networking](https://developer.apple.com/documentation/bundleresources/information-property-list/nsapptransportsecurity/nsallowslocalnetworking).
