Keshab requested denser chats, simpler reply drafting, faster and more truthful computer use, and broader reviewed personal sources. The chosen source scope is **PDF/Word folders and sourced suggestions**. ## Implemented scope

- Chat: one-line minimum composer, eight-line growth preserved, smaller padding and message gaps. Draft persistence, history, attachments, queueing and permission continuity use their existing paths.
- Reply drafting: generated reply appears first; conversation and optional intent remain visible. Context, local saved-item lookup and writing examples move into a default-closed disclosure. An always-visible summary discloses included context/style. Reload model, stale-input notice, unsent status and manual Copy/guarded Insert remain accessible.
- Computer use: post-action observations read the pinned observed window directly, avoiding another window enumeration. Unverifiable/suspected-no-op driver results include a fresh observation automatically. The verdict remains uncertain; no automatic input replay, mode change or confirmation inferred from a changed screen. Initial app/window ownership and generation checks remain enforced. This reduces tool calls; it does **not** remove the driver's measured approximately 2.5-second verification wait or establish a new live speed benchmark.
- Documents: a new reviewed source preview can include text-layer PDF and `.docx` alongside Markdown/text. Existing connected folders retain their original text-only scope. The original source table stays compatible with older six-value inserts; format scope lives in separate metadata. Source files remain read-only, and imported copies use existing provenance/correction/conflict/exclusion rules.
- Suggestions: explicitly select saved notes in the note editor's Suggestions disclosure, then enable prepared work in Daily brief settings. Current/corrected saved copies can produce private source-linked review cards through the selected isolated Claude/Codex model. Missing/conflicting copies are skipped. No automatic note search, folder refresh or account intake is added.

## Document reader boundaries

The packaged `atom-documents` executable receives bounded bytes over stdin, never source paths. PDFKit reads up to 100 pages of text layers; no OCR or encrypted PDFs. Word extraction accepts only the bounded main `word/document.xml` ZIP member, validates sizes/CRC and parses text with external entities disabled and DTD/entity declarations refused. No Office importer, archive writes, relationship following, macros or model calls.

Individual documents are at most 8 MiB; main Word XML at most 1 MiB; extracted text at most 256 KiB. Existing scan limits include 500 notes, 8 MiB extracted text, 5,000 entries, eight directory levels and a cooperative ten-second deadline; raw source reads add a 64 MiB aggregate budget. The owned helper has a five-second host deadline and a three-second CPU limit. These are parsing/resource bounds, not a general OS sandbox or a guarantee of secret detection. Malformed/no-text documents are visibly skipped; a missing reader fails explicitly. File identity/version is rechecked after extraction before publication.

## Private preparation boundary

At most 12 explicitly selected saved notes contribute Unicode-safe excerpts of 1,200 bytes each, with title, note ID, source path/state and collection time. Source/profile/config revisions are checked around model calls. Selection is durable and opt-out is explicit; future saved versions remain included until deselected. Source removal or mutation invalidates captured work. Notes remain ordinary notes, never standing facts or permission instructions.

With note input, the ordinary delivered/spoken brief is produced by a **separate note-free request using the same selected preparation profile**; note-derived lines are discarded. Notes-only preparation needs no ordinary model request. The existing daily admission budget applies to the combined run, which may therefore use two model requests under one admission and shared deadline. Review cards remain private Dashboard data with manual Copy; they cannot initiate sending, insertion, tasks or file writes. Local models remain an explicit backup, not the primary path.
