# T3 Code second source review — 2026-10-17

## Result

The existing roadmap covers most visible features. It gives too little weight to long-chat recovery, durable work state and recovery after interruption or usage limits. Those are the most useful lessons for Keshab's complaint that ATOM feels like a new assistant inside the same chat.

**Priority candidate:** keep the full archive, build bounded context for a resumed/switched provider, and let the agent retrieve earlier items from that chat. ATOM now has the first part. It does not yet have the latter two parts as one recovery path. This review proposes them; it does not implement or approve them.

The combined current plan is saved in [upgrade-roadmap.md](../docs/upgrade-roadmap.md). Existing feature deferrals and cost/permission decisions still apply.

## Corrections to the old notes

1. **T3 is not subscription-only.** It supports subscription tools and API-key/custom-endpoint configurations. `ClaudeProvider` explicitly labels API-key auth. Remove the inference that it does not need billing visibility because its main providers use subscriptions. ATOM's plan-only policy remains our own decision.
2. **Secret-file mode is verified in source.** [ServerSecretStore](https://github.com/pingdotgg/t3code/blob/f96aebeb4bbdaf2b3d05177bd115dad4b8b41a8b/apps/server/src/auth/ServerSecretStore.ts#L205) uses `0600` for secret files and `0700` for the directory. The old “file mode unverified” note is resolved. This is file storage, not proof of macOS Keychain use or encryption at rest.
3. **Desktop settings storage was found.** [DesktopAppSettings](https://github.com/pingdotgg/t3code/blob/f96aebeb4bbdaf2b3d05177bd115dad4b8b41a8b/apps/desktop/src/settings/DesktopAppSettings.ts#L29) owns local environment, exposure, Tailscale and related settings. The layer uses `DesktopEnvironment.desktopSettingsPath`.
4. **Archive retention is not sufficient context recovery.** The old notes mention the handoff cap but understate the retrieval tool and delivery state. Make this an explicit ATOM candidate before treating continuity as solved for arbitrarily long chats.
5. **ATOM Codex comparisons are stale.** Since ADR-137, Codex has checked host tools and real file-agent tasks. It still lacks several Claude worker capabilities. Text editing follows the active provider; background conversation summaries still use Claude.
6. **Continuing file permission is already built.** General idea 41 is delivered for one exact file in one chat under ADR-136, with live verification still pending. It must not remain an unqualified future item.
7. **Remembered approval scope is provider-specific.** T3's session-wide options are not equivalent to ATOM's persisted exact-file/chat permission. Do not use a generic “always allow” control to widen our scope.
8. **Devices has two meanings.** The right-panel device surface is for simulators/emulators. Paired client access belongs under Connections. The earlier distinction remains correct.
9. **ATOM already has some retrieval.** `apps/mac/src/kept-chats.ts` searches user-kept chat sections for context. The missing part is the own-chat, provider-handoff history recovery tool and budgeted replay described above; do not claim ATOM has no retrieval of any kind.
10. **The Git branch-discovery suspicion remains source-based.** `createIslandGit` still reads old helper grants, while project workers can create task branches without them. The fresh source comparison confirms the mismatch in inputs; a fixture/live project check is still needed before declaring the full UI defect reproduced. This audit changes no Git behavior.
11. **Provider switching is not unconditionally locked after the first turn.** `ChatView.tsx:2256` clears the picker lock when the server projection supports provider handoff; selection checks at lines 7531/7540 also depend on that flag. The old unconditional continuation-group-lock statement was incomplete. This capability branch also exists at the old revision.

## Revised priorities for ATOM

These are recommendations, not implementation authorization.

1. Finish the current three live acceptance workflows and the explicit file-grant restart/revoke sequence.
2. **Long-chat recovery:** own-chat paged retrieval, bounded provider context, preserved roles and explicit omitted-history references. Start with one provider transition and a test where the first requirement is outside the initial context selection.
3. **Work visibility and recovery:** clear provider/run/approval/limited states; enough saved operation identity to avoid replaying an edit or sending an answer twice after a restart. Add explicit limit retry before automatic provider switching.
4. **Prevent lost input:** durable drafts, attachment recovery and separate queued messages.
5. **Chat reading/copying/accessibility:** keep the existing C1/C3 plan, then reading position and richer Markdown.
6. Provider health/capability controls, followed by project/Git and settings improvements.
7. Keep the shared editor, phone auth redesign, images, cloud workers, optional API billing/fallback and preview/browser/simulator features subject to their existing deferrals or decisions.

No product feature, permission scope, provider fallback or billing mode was changed by this audit. The next implementation task should be chosen from the saved roadmap after reviewing these findings.
